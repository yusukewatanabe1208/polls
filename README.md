# ふつう度 — 医師向け2択診療判断サービス

`要件定義.md` に沿って実装したMVPです。
バックエンドは **Supabase**（認証・DB）と **ローカルJSON**（オフライン開発用）を切り替えられます。

## 起動

```bash
npm install
npm run dev        # http://localhost:9001
```

| コマンド | 内容 |
| --- | --- |
| `npm run check` | 指標計算ロジックの自己チェック（要件定義§19/§23/§24/§28の例を検証） |
| `npm run supabase:seed` | Supabaseにデモデータを投入（医師63人・質問13問・投票415件・コメント5件） |
| `npm run supabase:admin <名前orメール>` | 指定ユーザーを管理者にする |
| `npm run demo:status` | ローカルのダミーデータ件数を表示 |
| `npm run demo:purge-votes` | ダミー医師の投票・コメントのみ削除 |
| `npm run demo:purge-all` | ダミーデータをすべて削除 |
| `npm run seed:reset` | ローカルDB（`.data/`）を初期状態に戻す |

## Supabase のセットアップ（必須手順）

接続状態は **http://localhost:9001/setup** でいつでも確認できます。

1. **SQLを実行**：Supabase ダッシュボード → SQL Editor に
   **`supabase/setup_all.sql` を丸ごと貼り付けて実行**（1回で完了。何度実行しても安全です）
   - 個別に流す場合は `supabase/migrations/0001_init.sql` → `0002_favorites_and_ranking.sql` の順
2. **リダイレクトURLを登録**：Authentication → URL Configuration → Redirect URLs に
   `http://localhost:9001/auth/callback` を追加
3. **管理者にする**：一度ログインしたあと `npm run supabase:admin あなたのメールアドレス`
   （またはSQL Editorで `update public.profiles set is_admin = true where username = '...';`）

`.env` に `SUPABASE_ACCESS_TOKEN`（Supabase個人アクセストークン）を入れておくと、
`supabase:seed` / `supabase:admin` がManagement API経由で実行できます。

Google プロバイダの有効化は確認済みです。手順1が終わるまではDBが空のため、
ログイン後のプロフィール登録でエラーになります。

### バックエンドの切り替え

`.env` の `DATA_BACKEND` で指定します。

```
DATA_BACKEND=supabase   # Supabase（既定）
DATA_BACKEND=local      # ローカルJSON + モック認証（Supabase不要）
```

`local` では `.data/db.json` に保存され、デモアカウント（`@cardio_taro` など）で
すぐに動作を確認できます。

## 体験の流れ

```
質問を1問表示 → A/Bを選ぶ → 「回答する」で確定
   → 分布・自分の一致率・コメントが表示
   → 「次の質問へ」
   → 5問ごとに成績表
```

- ハンバーガーメニュー（右上）の項目は 普通度診断 / 質問を投稿 / 成績表 / 設定 / 管理画面（管理者のみ）＋ログアウト。
  「普通度診断」は `/play?go=question` を指し、全問回答済みでも直近の質問を開いて必ず質問画面になります。
  左上のタイトル「普通度診断」は `/play` で、全問回答済みなら完了画面を表示します。
  チェックボックス＋CSSで開閉するため、JavaScriptが動かなくても開きます。
  （祖先要素に backdrop-filter / transform を付けると fixed の基準が変わり開かなくなるので注意）
- お気に入り・プロフィールへは成績表の下部から移動できます。
- 画面はスマホ前提の設計です（本文18px、ボタン高さ52px、iOSの自動ズームを防ぐ入力欄）。

## 成績表（偏差値と10段階ランク）

普通度の分布を平均50・標準偏差10に換算した偏差値でランクを決めます。
**レベルが高いほど普通、低いほど独創的**です。スケールも左が独創的・右が普通の並びです。

| レベル | 偏差値 | 称号 | ニュアンス |
| --- | --- | --- | --- |
| 10 | 70〜 | 中庸を極めしベストドクター | 普通の頂点。中庸の境地 |
| 9 | 65〜70 | 人間ガイドライン | 驚くほどスタンダード |
| 8 | 60〜65 | 安心と信頼の正統派 | 多数派とかなり同じ判断をする |
| 7 | 55〜60 | 薄味正統派ドクター | 基本は王道。クセはほんのり |
| 6 | 50〜55 | いい塩梅ドクター | 王道と個性が半々くらい |
| 5 | 45〜50 | ひと味違う臨床家 | 個性的だが、やりすぎではない |
| 4 | 40〜45 | 濃口個性派ドクター | 判断にかなり自分の色が出る |
| 3 | 35〜40 | 我が道を征く臨床冒険家 | 王道は知っている。だが冒険する |
| 2 | 30〜35 | 白衣の異端児 | 多数派とは違う道を堂々と行く |
| 1 | 〜30 | 世紀末のマッドサイエンティスト | 常識という概念から最も遠い |

成績表に出す数値は**普通度の偏差値のみ**です（普通度そのものと多数派一致率はプロフィールで確認できます）。
下部の「これまで回答した質問」では回答履歴を**10問ずつ**表示し、「さらに10問を見る」で追加できます。
偏差値とランクだけを X / Instagram に共有できます（回答内容や本名は含みません）。
Instagramはウェブから直接投稿できないため、結果画像（1080×1080）をその場で生成し、
端末の共有シートに画像を渡します（スマホではInstagramを選んで投稿できます）。
共有シートが使えない環境では画像を保存してInstagramを開きます。
共有URLはリクエストヘッダーから組み立てるため、デプロイ先のドメインが自動的に入ります。

指標は保存せず、画面を開くたびに最新データから計算し直します（要件定義§30）。
普通度は他ユーザーの回答が増えると変わるため、ログインのたびに値が変動します。
指標を表示する画面は `dynamic = "force-dynamic"`、クライアント側のルーターキャッシュも
`staleTimes: 0` で無効化しているため、古い値が残りません。

## 入力の上限（`src/lib/limits.ts`）

| 項目 | 上限 |
| --- | --- |
| 質問本文 | 300文字 |
| 選択肢 | 「はい」「いいえ」に固定（入力不要） |
| 対象レベル | 研修医／非専門医／専門医 から必須選択 |
| コメント | 500文字 |
| 画像 | 1枚・10MB・PNG/JPEG/WebP/GIF |

同じ値をクライアント（入力欄のカウンター）・サーバーアクション・DBのCHECK制約で使っています。
画像は Supabase では Storage の `question-images` バケット、ローカルでは `.data/uploads/` に保存します。

## プロフィールと選択肢の扱い

- **ユーザーネームは登録後に変更できません。** 設定画面では読み取り専用で表示され、
  DB側のトリガー `profiles_lock_username` でも変更を拒否します。
- **本名は必須、医籍登録番号は任意**（いずれも非公開）。公開ビュー `public_profiles` には含めません。
  医籍登録番号は入力された場合のみ半角数字かを確認します。自己申告で、本サービスでは照合しません。
- **選択肢は「はい」「いいえ」に固定**。投稿者は質問文だけを考えます
  （`src/lib/limits.ts` の `CHOICE_A_LABEL` / `CHOICE_B_LABEL`、DB側は列の既定値）。
- 回答後の画面に「条件を追加して再投稿」があり、質問文に条件を足して新しい質問として出せます
  （投稿済みの質問は編集できないため、複製する形。「この質問を投稿して次の問題へ進む」で次へ）。

## 職業と指標の集計対象

プロフィールに職業（公開）を持ちます。医師のほか、看護師・薬剤師・理学療法士・
臨床工学技士（ME）など18種から選べます。

**普通度・偏差値・多数派の集計対象は「医師」の回答のみ**です
（`profiles.occupation = '医師'`）。医師以外も回答・コメント・質問投稿はでき、
自分の普通度は「医師と比べてどうか」を表す値になります。

## コメントのいいねと返信

- コメントに♥いいねを付けられます（1人1回、もう一度押すと取り消し）
- コメントへの返信（1階層）ができます
- プロフィールに「もらったいいね数」と自分のコメント一覧を表示します
- いずれもサーバーアクション直結で、JavaScriptが無くても動きます

## 質問のレベルと出題の絞り込み

質問には対象レベルを必ず設定します（`questions.level`）。

| 値 | 表示 | 想定 |
| --- | --- | --- |
| `resident` | 研修医レベル | 初期研修中に判断する場面 |
| `non_specialist` | 非専門医レベル | 専門外でも遭遇し、判断が必要な場面 |
| `specialist` | 専門医レベル | その領域の専門医が判断する場面 |

設定画面の「出題の設定」で、診療科・レベルを選んで出題を絞り込めます。
「すべてをシャッフル」を押すと絞り込みを外し、全問からランダムに出題します。
条件に合う未回答が無くなった場合は、自動的にすべての質問から出題します
（`src/lib/quizFilter.ts`、Supabaseは `profiles.filter_category_id` / `filter_level` / `shuffle_questions`）。

## 削除推奨

回答後の画面に「不適切につき削除推奨」があります。

| 押した人 | 結果 |
| --- | --- |
| 管理者（@watanabe など） | その場で削除 |
| 一般ユーザー | 3人が推奨した時点で削除 |

判定はSupabaseのトリガー `removal_requests_apply`（`apply_removal_request()`）が行うため、
どの経路から押しても同じ結果になります。1人1回までで、押すと次の質問へ進みます。

## デモ投票の自動入れ替え

デモ質問に**実ユーザーの回答が4人以上**集まると、その質問のデモ医師の回答とコメントを削除し、
実際の医師の分布に置き換えます。Supabaseでは `votes` のトリガー `votes_prune_demo`
（`prune_demo_votes()`）が担当するため、どの経路で投票しても必ず適用されます。
ローカルモードでも同じ閾値（`DEMO_PRUNE_THRESHOLD`）で動作します。

## 実装済みの主要ルール

- 回答前は分布・回答数・多数派・コメントを一切表示しない（§13）。Supabaseでは
  `get_question_result()` が未回答時に行を返さないため、DBレベルで担保しています。
- 選択 → 「回答する」で確定、確定後は変更不可、1ユーザー1質問1回答（§12/§14）
- 普通度＝「本人を除いた回答者のうち自分と同じ選択の割合」の平均（§16/§19）
- 多数派一致率＝多数派が存在する対象質問のうち一致した割合。50:50は分子・分母どちらにも含めない（§21/§24）
- 本人以外の回答数が20未満の質問は指標対象外（「回答募集中」）。値は管理画面で変更可（§28/§29）
- 指標は保存せず、閲覧のたびに最新データから再計算（§30）
- 勤務都道府県は非公開（`public_profiles` ビューから除外）
- 投稿後の質問本文・選択肢は編集不可。非公開化＋再投稿で対応（§10）

## コメント機能（要件定義§56からの追加）

要件定義ではMVP対象外でしたが、追加要望により実装しています。
原則1（回答前に結果を見せない）を壊さない設計です。

- 回答を確定するまでコメントの閲覧も投稿もできない（RLSでも担保）
- 未回答の質問にはコメント数も表示しない
- コメントには投稿者がA/Bどちらを選んだかを併記
- 投稿者本人と管理者が削除可能

## ダミーデータの削除

ダミーデータには全レコードに `is_demo = true` が付き、質問には画面上に「デモ」バッジが表示されます。
実データには付かないため、ダミーだけを削除できます。

| 操作 | 消えるもの | 残るもの |
| --- | --- | --- |
| ダミー投票のみ削除 | ダミー医師の投票・コメント | 質問・アカウント・実ユーザーの回答 |
| ダミーを全削除 | ダミーの質問・投票・コメント（＋ローカルではアカウントも） | 実データすべて |

- 管理画面「ダミーデータの削除」またはCLI（`npm run demo:purge-*`）から実行できます。
- Supabase側は `supabase/purge_demo.sql` を参照してください（アカウント削除には service_role が必要）。

## 高速化とキャッシュ

- 読み取りは React の `cache()` でリクエスト単位にメモ化（`src/lib/repo/index.ts`）。
  レイアウトとページで `getSession()` を呼んでも問い合わせは1回になります。
- 回答直後に次の質問IDを求め、`<Link prefetch>` で先読み。5問を連続で答えるとき、
  「次の質問へ」を押した時点でページが用意済みになります。
- 5問目では遷移先が成績表に切り替わり、こちらも先読みされます。
- 偏差値の算出（全ユーザーの普通度）は、質問ごとの集計を1度だけ作って
  O(投票数) で処理します（ローカル実装）。
- Supabase側は索引を追加：`votes(user_id, created_at desc)` / `votes(question_id, choice)` /
  `comments(question_id, status)` / `questions(created_at desc) where status='active'` /
  `favorites(user_id, created_at desc)`。
- 画像を10MBまで受け取れるよう、Server Actions のボディ上限を12MBに設定（既定は1MB）。

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/lib/repo/index.ts` | データアクセスの入口。環境に応じて実装を切り替え |
